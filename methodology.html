Short version

  • Polling VoteHub, DDHQ, Pollfinity, and USPollingData generic-ballot inputs are blended with source weights. 270toWin state race polls are blended where candidate sides can be identified. RealClearPolling and Race to the WH are checked, but only blended when their fetched pages expose stable row-level data.
  • Fundamentals The baseline blends race ratings, state lean, recent Senate results, incumbency, candidate overperformance history, finance efficiency, and population growth.
  • Uncertainty Simulations include national error, correlated regional polling error, turnout miss, race error, primary scenarios, ranked-choice effects, and independent-candidate uncertainty.
  • Confidence A high simulation count reduces Monte Carlo noise, but it does not remove sparse polling, unresolved primaries, or late-cycle campaign shocks.
  • State response Competitive and elastic states move more with the national environment; less elastic states move less.
  • Calibration Each run writes a diagnostic check against MIT/MEDSL historical Senate results so model error can be tracked over time.
  • Control math Independent candidates are counted by likely caucus for chamber control. Tipping power comes from simulations where that exact race changes control.
  • Publishing GitHub Actions runs the generator daily and writes one shared `data/forecast.json` file for everyone.
